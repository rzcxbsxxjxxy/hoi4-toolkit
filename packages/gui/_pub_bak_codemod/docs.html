📖 使用教程 HOI4 模组工作台

这是什么

一套本地运行的 HOI4 模组辅助工作台：把游戏目录与创意工坊模组挂进来， 就能可视化浏览国策树 / 科技树 / 决议树、拖拽编辑界面 .gui、 做无损改写、跑体检与跨文件重命名。 所有解析走自研的 Clausewitz 无损解析器 —— 改写后文件里你手写的注释、空行、缩进都会原样保留。

和同类工具的区别

常见工具（HOI4 Mod Utilities 等）定位在编辑器内写代码：语法高亮、补全、跳转、校验。 本工作台定位在跨文件的整体视图：把散落在几十个文件里的国策/决议/科技/界面元素 汇总成一张图，看清结构、来源归属和坐标关系，再一次性回写。 两边互补，不冲突。

快速开始

  1. 打开 打开工程（或直接进 ⚙ 设置），填游戏安装目录。 点「自动检测」，工具会扫描 Steam 库、列出所有候选路径，选一个即可。
  2. 在模组区勾选要挂进来的模组。可以「扫描创意工坊」批量列出 workshop/content/394360/*，也可以在输入框粘贴本地模组目录手动添加。 模组顺序 = 游戏加载顺序，可用上下箭头调整；越靠后优先级越高。
  3. 点「保存并应用」→「重新载入」。重载后所有页面（国策/科技/决议/GUI）都会按新的来源组合重建索引。

看不到模组内容？先查这三件事

  • 目录里有没有 .mod 文件 —— 这是模组识别的特征文件，没有就识别不出来。
  • 模组是否声明了 supported_version，设置页会显示版本兼容提示。
  • 如果只勾了模组没勾基础游戏，原版内容会缺失；基础游戏应当始终排在最前面。

核心概念：来源的三层语义

挂了多个来源后，同一个国策/决议/文件可能同时存在于原版和模组里。 工具用三个字段描述「它到底是谁的」，理解这组语义是使用筛选功能的前提：

字段含义
base 内容归属：最终生效的那一份，来自只读的基础游戏。 注意 —— 若模组把内容全量覆盖了，这一档会是空的， 所以「仅基础游戏」筛选结果为空是正常的，不代表解析失败。
origin 出身：原版（覆盖链里包含只读基础游戏） 或 模组（原版根本没有这个东西，模组独创）。
overridden 是否被改写：origin=原版 但最终生效的那份来自模组。 标记成 改写，是排查「为什么我的改动不生效」的第一入口。

徽标图例

原版 原版内容，未被模组改动　 改写 原版有，但被模组覆盖　 新增 原版没有，模组独有　 模组 生效来源为模组

典型用法

想知道「KR 到底改了原版哪些国策」→ 国策页来源筛选选 改写； 想知道「KR 新增了什么」→ 选 模组新增。 这两个数字在树列表下方的统计条里会直接给出。

页面导览

工作台GUI 预览与拖拽

左侧文件树列出所有 .gui，中间画布按真实坐标渲染，右上是缩放/适应/贴图/名称开关。 在画布上拖动元素会进入待改区（右上「待保存 N」）， 确认后点「保存」—— 回写是行级最小差异，只改动你碰过的那几行，其余字节原样不动。

  • 适应：自动缩放铺满视口，找元素时先按一下。
  • 贴图：开关 sprite 背景。模组常用 png（原版多用 dds），工具两者都认。
  • 名：显示元素名，调试坐标时非常有用。

界面设计器四栏可视化编辑

文件树 / 画布 / 元素树 / 属性网格。相比工作台多出：

  • 属性网格：按语法枚举给出候选值，不用手敲字符串。
  • 增删元素：选中后按 Delete 删除，属性网格里可加子块。
  • 吸附：设置页可开「拖拽吸附网格」并指定格宽，对齐时省事。

国策树结构、体检与坐标回写

  • 来源筛选：按上一节的三层语义过滤，树列表会显示每棵树的来源徽标。
  • 拖拽改坐标：拖动国策节点后保存。若该节点写了 relative_position_id，写回的是相对父节点的偏移，而不是绝对坐标 —— 这是官方的相对布局语法，写绝对值会破坏相对关系。
  • 体检：检查悬空依赖、重复 id、坐标重叠、缺失本地化等， 结果分 error / warning 两级列在右侧。

坐标重叠不一定是 bug

互斥分支（如两个互斥的国策路线）用同一坐标是官方惯用写法 —— 因为同一时刻只会有一条生效。体检对这种情况做了消歧，不会误报。 另外 id 前缀不同的树属于「多国共享树」，也不算冲突。

科技树两级分类与隐藏科技

科技有两层分类，容易混淆：

来源作用
technology_categories横向顺序表，决定左右排列次序，不是显示分组
technology_folders真正的显示分组，带 ledger：army / air / navy / civilian / hidden

「隐藏科技」有两类，勾选「隐藏科技」后都会显示：

  • 没有 categories 的科技 —— 游戏里没有标题栏，画布上画成米色虚线框。
  • ledger = hidden 的文件夹里的科技 —— 游戏里整个分组都不显示。

另有一部分 doctrine 分类声明了但当前没有科技（由脚本运行时填充）， 画布上标为「空 · 由脚本填充」而不是隐藏，避免误判成解析失败。 科技普遍是多分类的，筛选用的是包含判断而非等值。

决议树分类卡片墙

按 decision_category 组织成卡片墙，绿左边条表示该分类来自模组。 顶部统计条给出原版 / 模组新增的条数，点分类钻取到具体决议， 右侧检查器显示生效来源与覆盖链。

内容生成脚手架

选择产物类型（国策 / 决议 / 事件 / 本地化等），填字段后生成可直接落盘的 .txt / .yml。可以「填示例」看格式，生成结果支持一键复制。

IDE / 体检编辑与全量校验

IDE：基于符号表的补全与跳转，适合精修单个文件。 体检：对当前挂载的全部来源跑校验，按严重度分卡片汇总，点条目可跳到对应文件。

进阶：GUI 坐标是怎么算的

如果你想改 .gui 却总觉得位置对不上，这一节是必读的。 我们的渲染链路逐字对齐了 VSCode 扩展 HOI4 Mod Utilities 的实现 （扩展 common.js 里的 r() / o() / u()）， 并在原版 23558 个样本上比对通过。下面是几个最容易踩的坑：

1. 锚点来自 orientation，对齐点来自 origo —— 不是同一个东西

orientation 决定父级的哪个点作为坐标原点（锚点，9 种取值）； origo 决定元素自身的哪个点对齐到那个锚点（对齐点）。 把两者当成同一个东西，元素会整体平移半个自身宽度。 缺省对齐点是 upper_left，只看 origo，与 orientation 无关。

判例不能随便挑

用某个元素「看起来对」来反推缺省行为是危险的 —— 比如 mainmenu_panel_upperright 贴齐 1920，常被当作「对齐点 = 锚点」的证据， 但它显式写了 origo，对缺省行为零信息量。 验证缺省行为必须挑「没有写该字段」的样本。

2. % 和 %% 是两种不同的单位

'100'   → 100 px（绝对值）
'100%'  → 父尺寸 × 100 / 100
'100%%' → 父尺寸 × 100 / 100 − 自身坐标偏移

%% 的语义是「延伸到父级边界」：先按百分比算，再扣掉自己的坐标偏移。 原版里有 800 多处 %% 尺寸和几十处负尺寸， 负尺寸表示向反方向延伸，不能提前取绝对值。

3. 图标 / 按钮没有 size 块

iconType / buttonType 通常不写 size， 它们的绘制尺寸只能取自 sprite。 如果按「没写 size 就是 0」处理，画布上所有图标都会变成 0×0 的空框 —— 这是早期版本最明显的一个位置错误。现在尺寸会取 sprite 宽高再乘 scale。 instantTextBox / textBox 同理，取 maxWidth / maxHeight。

4. 传给子元素的父尺寸是「声明值」

子元素的坐标系用的是父级 size 的声明值，不是父级最终绘制宽度 （绘制宽度可能被 min 或 %% 重算过）。 用绘制宽度会让整棵子树偏移。

5. 其他几个会影响位置的机制

机制效果
margin容器级：子坐标系扣除 margin，整体右下平移
show_position嵌套 containerWindowType 写了它，就忽略 position
parent="name"递归累加被引用元素的偏移（带环检测）
orientation = left原版有 9 处用到，语义是「左边中点」。扩展的锚点表漏了这个键，会 fallback 算错；我们保留了特例

快捷键

按键作用

常见问题

改完保存，游戏里没变化？

先确认你改的是生效的那一层。如果原版同名文件还在更靠后的位置被模组覆盖， 你的改动会被覆盖掉。用来源徽标（改写）确认哪份最终生效。

为什么筛选「仅基础游戏」是空的？

因为 base 指的是「最终生效的那份来自只读基础游戏」。 当你挂的模组把内容全量覆盖了，这一档自然为空 —— 这是预期行为，不是 bug。 要对比原版请去掉模组来源，或改用 origin 维度筛选。

模组贴图显示不出来？

模组喜欢把原版的 foo.dds 换成 foo.png，但声明里照抄不改扩展名。 工具会按同 stem 依次尝试 dds → tga → png； 若模组目录里确实没有，会回退到原版同名文件（很多模组只是重新声明 sprite 复用原版贴图）。

无损回写会不会破坏我的格式？

不会。解析器保留 token 流与原始下标，序列化时按原文拼接， 只替换被改动的那几个 token 的字面量。未改动的文件逐字节相同。 保存时会在同目录留 .bak。

能撤销吗？

保存前所有改动都在「待保存」区，可直接丢弃重来； 保存后靠同目录的 .bak 备份文件恢复。
