# 在线部署方案（多用户 · 各自本地游戏 · 免费优先）

> **一句话结论：这个工作台不可能"部署到云上"给所有人共用。**
> 它的核心能力是**读使用者本机的 HOI4 目录**（`--base`）和**写使用者本机的模组目录**（`--mod`）。
> 云端容器里没有这些盘，任何人挂不上自己的游戏。
>
> 所以「在线」的正确含义不是「把服务托管出去」，而是：
> **让每个使用者能在自己机器上 effortlessly 跑起一份，并且能远程访问它。**
> 下面按这个理解给方案。

---

## 零、先看清约束（决定了后面所有选择）

| 约束 | 说明 | 对方案的影响 |
|---|---|---|
| **必须读本机文件** | 游戏目录由 `--base`/env 传入，运行时 `readFileSync` 直读磁盘 | 服务必须跑在**使用者自己的电脑**上，或至少能访问他的盘 |
| **会写盘** | `/api/fs/write`、`mkdir`、`rename`、`delete` 供 IDE 保存与脚手架落盘 | 需要可写路径；对象存储做不了 rename |
| **零依赖 + Node 22 原生 TS** | 无 `npm install`，靠 `--experimental-strip-types` | 分发就是「拷一个文件夹」，没有安装成本 → **极适合一人一份** |
| **单进程内存索引** | 国策 3 万、贴图 7.2 万、引用图 3.4 万 | 吃 512MB–1GB；不适合无状态多副本 |
| **默认绑 `0.0.0.0:5173` 且无鉴权** | 任何人能读写你的磁盘 | 一旦暴露公网 = **任意文件写**，硬门槛 |

**关键推论**：既然服务必须跑在每个人自己的机器上，那"部署"的本质就退化成
**「怎么让 100 个人各自方便地跑起它」+「怎么让他们在别的设备上访问它」**。
这就落到了下面两类方案。

---

## 一、推荐方案

### 方案 A ——「本地一键启动 + 可选外网访问」（★ 最推荐，$0）

每个使用者在自己电脑上跑一份，本地浏览器访问；需要时用免费隧道从手机/平板访问。

```
使用者的浏览器 ──> 127.0.0.1:5173(他自己的机器)
                        │
                        └─(可选) Cloudflare Tunnel / Tailscale ──> 公网 HTTPS
```

**为什么这是唯一「免费且正确」的形态**
- 数据一个字节都不出本机，磁盘读写、Steam 路径、中文文件夹路径原样可用
- 不需要服务器、不需要域名、不需要备案、不需要 GPU
- 零依赖 → 分发成本为零（见方案 B）

**外网访问三选一（都免费）**

| 工具 | 免费额度 | 特点 |
|---|---|---|
| **Cloudflare Tunnel** | 完全免费，无带宽上限 | `cloudflared tunnel --url http://localhost:5173` 直接给 `*.trycloudflare.com` 公开地址，不用开入站端口 |
| **Tailscale Funnel** | 个人版免费 | 只在你自己的设备间暴露，带加密 + ACL，最安全 |
| **ngrok / frp** | 免费档有流量/带宽限制 | 仅够演示，长期用会撞限 |

> 隧道只是"把你本机的 5173 端口映射成一个 HTTPS 地址"，
> **不会也不能**让别人挂载他自己的游戏——每个使用者各跑各的。

⚠ **上线前必做两件事**（现在服务无鉴权且能写盘）
1. **加访问控制**：Cloudflare Access / Tailscale ACL，不要裸奔公网
2. **绑 `127.0.0.1`** 而不是 `0.0.0.0`，让隧道成为唯一入口

---

### 方案 B ——「打包成桌面应用」（★ 分发给别人的最佳形态，本项目已采用）

本项目**已用 Electron 打包成桌面程序**：根目录 `main.cjs` 是 Electron 主进程，托管编译后的后端
`server.mjs`（经 `ELECTRON_RUN_AS_NODE` 由 Electron 自带 Node 拉起，用户机**无需装 Node**），
前端 `packages/gui/public` 由 Electron 原生窗口承载。一键出包：`build-installer.bat`（内部即
`electron-builder --win nsis`），产出 `dist/HOI4-Toolkit-Setup-<版本>.exe` + `latest.yml`（自动更新）。

- 使用者双击安装包安装后，桌面 / 开始菜单出现「HOI4 工具链」，开箱即用，**完全不需要装 Node、不需要命令行**。
- 安装包 ~80–120MB（Electron 运行时体积），但生态成熟、调试方便，且自带自动更新（`electron-updater`）。
- 也可改用 Tauri（安装包 ~5–15MB，内存占用更低），但本项目当前锁定 Electron。

打包后它就是**一个本地 App**，每个使用者装在自己电脑上，读自己的游戏目录 ——
**"让不同使用者用自己的本地游戏"天然成立**。

配合方案 A 的隧道，还能让没装 Node 的人从手机看。

---

### 方案 C ——「容器化 + 挂载游戏目录」（适合自建 VPS，**不满足你的核心需求**）

一台便宜 VPS，Docker 里跑，**把游戏目录 bind-mount 进去**。

```dockerfile
FROM node:22-slim
WORKDIR /app
COPY packages ./packages
ENV HOI4_DOCS=/game
EXPOSE 5173
CMD ["node", "--experimental-strip-types", "packages/gui/src/server.ts"]
```

```bash
docker run -d -p 5173:5173 \
  -v "/c/Program Files (x86)/Steam/steamapps/common/Hearts of Iron IV:/game:ro" \
  -v "/d/hoi4/mods:/mods" \
  hoi4-workbench
```

- 游戏本体挂 `:ro`（只读更安全），模组目录给可写卷
- **致命限制**：挂进去的是**你这一台机器的盘**。别人访问到的是你的游戏，不是他自己的。
  → 只适合「我一个人想在 VPS 上跑」或「团队共用一份公共模组库」，
  **不适合**「每个人用自己的本地游戏」。

免费层现实：Oracle Cloud Always Free（1 ARM 实例，常缺货）、Google/AWS 12 个月试用。
纯免费稳定的容器托管基本没有了（Fly.io 已取消新账号免费额度，Railway 是 $5 试用券 30 天过期）。

---

### 方案 D ——「只读在线演示」（真免费，适合放作品 / 分享界面）

把**脱敏后的示例数据**（一小份 common/ + 假地图资产）打进镜像，禁掉所有写盘路由。

- Render Free：750 小时/月、15 分钟空闲休眠、冷启动 30–60 秒，个人工具够用
- **必须**加 `READONLY=1`，让 `/api/fs/write` 等直接 403，否则别人能在你的容器里写文件
- 这个模式**只能看演示数据**，使用者挂自己的模组做不到

## 二、方案对比（对着「各自本地游戏」这个需求打分）

| | A 本地+隧道 | B 桌面打包 | C 自建容器 | D 只读演示 |
|---|---|---|---|---|
| 费用 | **$0** | $0 | ¥30/月或试用 | **$0** |
| **各人用各自本地游戏** | ✅ | ✅ | ❌（共用你的盘） | ❌ |
| 写盘（IDE / 脚手架） | ✅ | ✅ | ✅ | ❌ |
| 数据不出本机 | ✅ | ✅ | ❌ | — |
| 要用户装 Node | ⚠ 是（B 可免） | ❌ 不用 | ❌ | ❌ |
| 使用者电脑要开着 | ✅ | ✅ | ❌ | ❌ |
| 需要鉴权 | 必须加 | 不需要 | 必须加 | 建议加 |
| 适合"发给朋友用" | ⚠ 需装 Node | ✅ **最佳** | ❌ | ❌ |

**我的建议**：
- **自己用 / 小范围分享** → **A**（零成本，一分钟起）
- **想让别人也能用上自己的游戏** → **B 桌面打包**（这是"分发"的标准解法）
- **只做展示** → **D**

A 和 B **不冲突**：B 是"怎么分发"，A 是"怎么远程访问"。

## 三、无论哪个方案都该先做的三件事

1. **加鉴权**。当前服务任何人都能调 `/api/fs/write` 写你的磁盘。这是**上线前的硬门槛**。
2. **默认只读 + 显式可写**。加 `READONLY=1` 环境变量，`fs/write`、`mkdir`、`rename`、`delete` 直接 403；
   可写目录收敛到挂载卷内，防目录穿越。
3. **限流与超时**。公开实例挂反向代理做基础限流；`/api/worldmap/meta` 这类重接口加缓存
   （冷启动那 30 秒会连击）。

## 四、当前技术栈对部署的有利条件

- **零 npm 依赖** → 不用 `npm install`，Dockerfile 只有一行 `COPY`，镜像 ~150MB；
  分发给用户就是「拷一个文件夹 / 解压即用」
- **端口用 `--port` 参数**（`node ... server.ts --port 8080`）→ 同一份代码本地 5173、云上用平台端口；启动器已自动处理占用冲突
- **无热重载、启动即构建索引** → 启动行为可预测，适合 scale-to-zero，也适合打成桌面 App
- **`gui-settings.json` 已 gitignore**、路径只从 CLI/env 读 → 源码里没有本机绝对路径，
  可以直接进公共仓库，别人 clone 下来填自己的路径即可

## 五、最小落地（已完成）

「自动探测 Steam 路径 → 启动服务 → 打开工作台」已经做好，且**已打包为 Electron 桌面程序**：

- **`build-installer\build-installer.bat` / `.sh` / `.mjs`**：一键出 NSIS 安装包。`.bat`/`.sh` 只是入口，流水线本体是零依赖跨平台的 `build-installer.mjs`（check → out → server → stage → package → clean + 核对产物）。产出 `..\toolkit-installer\HOI4-Toolkit-Setup-<版本>.exe` + `latest.yml`。`npm run dist` 委派给它。
- **`main.cjs` / `preload.cjs` / `splash.html`**：Electron 主进程、预加载、启动闪屏；后端 `server.mjs` 由 Electron 自带 Node（`ELECTRON_RUN_AS_NODE`）拉起，用户机**无需装 Node**。
- **`新手指南.md`**：写给第一次用的人的图文说明（方式一桌面程序免装 Node / 方式二纯 Web 需 Node 22.6 → 如何加模组 → 常见问题）。

新手实际流程（推荐）：双击 `build-installer\build-installer.bat` 生成安装包 → 安装 → 桌面双击「HOI4 工具链」，完事。无需装 Node、无需配置路径（Steam 标准安装下开箱即用）。

后续可选增强（按需，非必需）：
1. 开启自动更新：把 `version.json` + `latest.yml` + 安装包放到同一目录，设 `HOI4TK_UPDATE_URL` 指向它（桌面程序 `electron-updater` 会自动检测并提示安装）。
2. 想在手机/别的设备用 → 加一行 `cloudflared tunnel --url http://localhost:5173`（方案 A，务必加访问控制）。
3. 只读演示分享 → 加 `READONLY=1` 打成只读实例（方案 D）。
